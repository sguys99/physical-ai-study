## §1. 토픽 1개 작성 표준 절차 (7단계)

절차는 여기서 한 번만 정의하고, 이후 토픽 목록은 체크박스로만 추적합니다.

| # | 단계 | 주체 | 하는 일 |
|---|---|---|---|
| 1 | **컨텍스트 로드** | 스킬 | `/pai-course-author W1-M3` 호출 → 마스터플랜의 해당 모듈 섹션 + §2(회사 스택) + §3(갭 분석) + CLAUDE.md 작성 표준을 자동 주입. **플랜 없이 일반 지식으로 쓰면 회사 스택 연결이 빠져 가치가 절반이 됩니다.** |
| 2 | **최신성 검증** | 스킬 | 버전이 빠르게 바뀌는 항목(LeRobot · mujoco_playground · MuJoCo · DualMap · Isaac Lab)만 공식 문서로 설치법·API 재확인. 출처 URL과 확인 날짜를 frontmatter `sources_checked`에 기록 |
| 3 | **초안 생성** | pai-agent | `lesson.md` + `practice/` + `labs/`를 §2 표준대로 작성. **이 단계에서 윤문하지 않습니다** |
| 4 | **정적·실행 검증** | pai-agent | frontmatter 스키마 · 상대링크 · Mermaid 파싱 확인. CPU에서 돌아가는 코드는 직접 실행. GPU가 필요한 항목은 `> ⚠️ 미검증(GPU 필요)` 배지를 달고 예상 출력만 명시 |
| 5 | **윤문** | /humanize-korean | `lesson.md` **본문만** 윤문 |
| 6 | **보존 검증** | 스킬 | 윤문 전후 diff 대조. 보존 대상이 바뀌었으면 롤백. 변경률 판정은 **보호 구간 비율에 따른 지표**를 씁니다(아래 박스). 보존 검증에는 **한글 수사 계수 대조**를 포함합니다(§9.3·§9.5) |
| 7 | **마무리** | — | 본 문서 체크박스 `[x]` 갱신 + 이모지 컨벤셔널 커밋 (예: `:white_check_mark: W1-M3 diffusion-ddpm-dit 완료`) |

> ⚠️ **윤문 철칙 — 아래는 한 글자도 바뀌면 안 됩니다.**
> 코드블록 · 셸 명령 · URL/arXiv ID · **LaTeX 수식** · **Mermaid 블록** · 수치·하이퍼파라미터 · frontmatter · 영문 약어 · 모듈 ID · 토픽 슬러그.
> `/humanize-korean`은 **문체·리듬·표현만** 바꿉니다. 윤문 뒤 실습 코드와 수식이 그대로인지 반드시 확인합니다.

> 📌 **모든 lesson은 strict 경로**: `/humanize-korean`은 `register: course`면 길이와 무관하게 strict(5인 파이프라인)로 승급하고, 8,000자 초과도 같은 결과입니다. 집필된 lesson은 전부 26,000자를 넘으므로 **티어와 상관없이 strict**이고, fast보다 시간이 더 걸립니다.

> 📏 **변경률 판정 지표 — 갈림선은 티어가 아니라 보호 구간 비율입니다** (2026-08-05 개정, 근거는 §9.6)
>
> | 보호 구간 비율 | 판정 주지표 | 정상 밴드 |
> |---|---|---|
> | **35% 이상** | **산문 라인 변경률**(코드펜스·표 행·`$$` 블록 제외) + **잔존 burden 감소율** | 라인 20~50% · burden 80%↓ 이상 |
> | 35% 미만 | 전체 문자 변경률 | 5~30% |
>
> 보호 구간 = 코드펜스 · Mermaid · LaTeX(블록 + 인라인) · 표 행 · frontmatter. **전량 보존 대상이라 문자 변경률의 상한이 구조적으로 막힙니다.**
>
> **원래 규정은 "Tier A는 산문 라인으로 판정"이었는데 티어가 원인이 아니었습니다.** Tier C인 W1-M3(보호 54.2%)와 W1-M4(55.2%)가 각각 문자율 1.86% · 1.06%로 Tier A와 똑같이 나왔습니다. W1-M2는 1.48%, W1-M5(보호 39.0%)는 2.32%입니다. **집필된 5개 lesson이 전부 35%를 넘으므로 사실상 모든 lesson이 산문 라인 판정 대상**이고, 35% 미만 규칙은 짧은 산문 문서용으로 남깁니다.
>
> **문자 변경률이 5% 미만이라는 사실은 그 자체로 저윤문 근거가 아닙니다.** 저윤문은 `주지표 하한 미달 + S1 잔존`일 때만입니다. 문자율만 보고 재윤문을 지시하면 **과윤문을 유발**합니다 — W1-M2는 1.48%였지만 S1 5/5 해소에 산문 라인 34.2% 변경이었습니다.
>
> 판정이 애매하면 `naturalness-reviewer`의 verdict(`accept` / `rewrite_round_2`)를 우선하세요. 문자 수보다 신뢰할 만합니다.

> 💡 **후속 명령**: "이 토픽 다시" → 1단계부터 / "practice만 보강" → pai-agent 재호출(해당 산출물만) / "윤문 다시" → 5–6단계만.

## §3. 공통 규약 (웹 배포 대비 — 지금부터 강제)

### 3.1 frontmatter 스키마 (`lesson.md` 필수)

```yaml
---
module: W1-M3                          # 마스터플랜 모듈 ID와 1:1
week: 1
order: 3                               # 폴더 숫자 prefix와 일치
title: "Diffusion 계보: DDPM → DiT"
slug: diffusion-ddpm-dit
tier: C                                # A(갭 집중) | B(혼합) | C(강점 압축)
priority: P0                           # P0 | P1 | P2
prereq: [W1-M1]
tags: [generative, diffusion, dit]
est_reading_min: 25
updated: 2026-08-01
sources_checked: 2026-08-01            # 최신성 검증 날짜
---
```

정적 사이트 빌드([P2], W4)는 이 frontmatter만 스캔하면 목차·순서·태그·선수 관계를 전부 재구성할 수 있습니다. 그래서 지금 지켜두면 나중에 재작업이 없습니다.

### 3.2 시각자료 — lesson 하나에 최소 4종

| 유형 | 도구 | 쓰는 곳 |
|---|---|---|
| **비교표** | Markdown 표 | 계보 비교, 스펙, 트레이드오프, 하이퍼파라미터, sim2real 요인×대응 — 비교는 무조건 표 |
| **흐름·계보 다이어그램** | Mermaid `flowchart` / `graph LR` | 파이프라인, 데이터 흐름, 논문 계보 트리 |
| **타이밍·주파수 다이어그램** | Mermaid `sequenceDiagram` | 제어 루프 주파수 예산, 지연과 chunking의 관계 |
| **아키텍처 블록도** | ASCII 코드블록 | **텐서 shape·차원 라벨이 필요한 곳.** Mermaid는 차원 표기가 지저분해지므로 여기만 ASCII |

- 4종 최소 구성: ① 계보·지형 ② 아키텍처 ③ **회사 스택 연결도** ④ 비교표
- Mermaid는 코드펜스로 씁니다(GitHub와 대부분의 정적 사이트 생성기가 그대로 렌더).
- 이미지 파일은 `img/{module-id}-{slug}.png`, 참조는 `../../img/`. 롤아웃 mp4·학습 커브 같은 대용량은 `artifacts/`(gitignore).

### 3.3 명명 규칙

- 주차 폴더 `w{N}-{slug}` / 토픽 폴더 `{NN}-{topic-slug}` — **숫자 prefix가 정렬 순서**
- 토픽 번호는 모듈 번호와 1:1 (`W2-M3` → `course/w2-policy-vla/03-vla-lineage/`)
- 전부 소문자 kebab-case, 공백 금지. 링크는 상대경로

### 3.4 practice 코드 규약

- **단일 소스**: `.py`가 원본(jupytext percent 포맷 `# %%` 셀 구분), `.ipynb`는 생성물.
  ```bash
  jupytext --set-formats py:percent,ipynb 01_fsq_tokenizer.py   # 최초 1회
  jupytext --sync 01_fsq_tokenizer.py                            # 이후 동기화
  ```
  둘 다 커밋하되 **노트북 출력은 비우고** 커밋합니다. 노트북은 커널 재시작 후 Run All로 완주되어야 합니다.
- **스모크 경로 우선**: 무거운 학습에는 `--smoke` 플래그(수백 스텝, 수 분)를 먼저 붙여 완주되게 하고 본 학습은 그 뒤에. GPU 시간 낭비와 입문자 좌절을 동시에 막는 장치입니다.
- **headless 고정**: `MUJOCO_GL=egl`, 뷰어를 띄우는 코드 금지. 결과는 `artifacts/{module-id}/`에 mp4/png로 저장.
- **읽기 쉬운 것 > 최적화**. 핵심 수식이 코드 어디에 대응하는지 `# eq.(3)` 형태로 주석.
- `requirements.txt`는 버전 고정. 30분 이상 걸릴 학습은 문서에 **예상 소요 시간·GPU 시간**을 명시.

### 3.5 미검증 배지

집필 환경은 CPU 로컬(WSL)입니다. GPU가 필요해 집필 시점에 실행할 수 없었던 절차에는 배지를 답니다.

```markdown
> ⚠️ **미검증(GPU 필요)** — 아래 절차는 집필 시점에 실행 검증되지 않았습니다.
> 예상 소요: A10G 기준 약 40분. 실행 후 결과를 `docs/progress.md`에 기록하고 이 배지를 제거하세요.
```

배지가 남아 있는 절차는 §2의 5번(실행검증) 체크박스와 짝을 이룹니다.

### 3.6 모르는 것은 모른다고 쓴다

회사 내부 구현(FSQ 모델의 실제 구조, SONIC 정책의 실제 입력 등)은 **추측하지 않습니다.** 대신 `notes/questions-for-team.md`에 질문으로 적립하고, lesson 본문에는 "팀 확인 필요" 표시만 남깁니다. 이 질문 목록이 캡스톤(W4-M5)의 검증 질문 리스트가 됩니다.

## §4. 분량 3단계 티어

총량은 비슷하게 유지하되 시간을 **갭 영역에 몰아줍니다.** 제어·ML·LLM은 기초를 생략하고 바로 심화로, 로봇 시뮬·SLAM은 기초부터.

| Tier | **산문 문자** (주지표) | 모듈 | 근거 |
|---|---|---|---|
| **A** 갭 집중 | **24,000~28,000** | W1-M1, W1-M2, W2-M1, W2-M2, W3-M1, W3-M4, W3-M5, W4-M3 (8개) | 시뮬 실무 · 모방학습 파이프라인 · RL 학습 실무 · sim2real/미들웨어 · 3D 비전/SLAM. **W1-M1은 로봇 산업 지형 자체가 갭 영역**이라 A(2026-08-05 정정, §9.6). W3-M4(SONIC)는 회사 WBC 본체이자 "가장 정독할 논문"이라 예외적으로 A |

### 9.6 §4 티어표와 §1 판정표 개정 — 실측 5건이 말한 것 (2026-08-05)

§9.2가 "W1-M3·M4 두 모듈이 끝난 뒤 §4 티어표 개정 여부를 결정한다"고 미뤄둔 항목입니다. W1 5개 lesson이 전부 완성돼 표본이 찼으므로 개정합니다.

#### 발견 1 — 깨진 것은 Tier C 하나뿐이었습니다

§9.2의 환산선(A4 1장 ≈ 4,400~5,900자)으로 기존 규정을 문자로 풀면 A는 35,200~59,000, B는 22,000~41,300, C는 13,200~23,600입니다. **A와 B는 전부 밴드 안**입니다(M2 46,887 · M1 40,676 · M5 26,158). C만 M3 +34%, M4 +51%로 벗어났습니다. 즉 "티어 규정이 전반적으로 헐겁다"가 아니라 **C의 밴드만 현실과 어긋났습니다.**

#### 발견 2 — 원인은 산문이 아니라 구조물입니다

**Tier C의 "강점 압축"은 산문에서는 실제로 작동했습니다.** C의 산문(17,960 · 20,067)은 B 하단(M5 17,730)과 같은 수준이고 A(26,520)보다 확실히 적습니다. 설명을 줄이라는 티어의 지시는 지켜졌습니다.

깨진 것은 구조물입니다. C의 구조물(13,608 · 15,564)이 B의 M5(8,428)보다 **1.6~1.8배** 크고 A의 M2(20,367)에 근접합니다. 이유는 단순합니다 — **수식 유도·비교표·블록도의 양은 티어가 아니라 주제의 기술 밀도가 정합니다.** DDPM의 ELBO→$\mathcal{L}_{\text{simple}}$ 유도와 FM의 CFM 정리 증명은 "강점 영역이니 압축하라"는 지시로 줄일 수 있는 것이 아니고, 줄이면 모듈의 본체가 사라집니다.

→ **개정: 티어의 규정 대상을 총 문자에서 산문 문자로 바꿉니다.** 구조물은 티어와 독립인 변수로 분리하고 규정하지 않습니다. 새 밴드는 위 실측에서 잡았습니다(A 24,000~28,000 · B 17,000~25,000 · C 17,000~21,000).

이 개정으로 **W1-M3·M4의 "초과"는 초과가 아니게 됩니다.** 산문 17,960 · 20,067은 C 밴드 안입니다. §9.2·§9.4의 초과 기록은 당시 규정 기준의 사실 기록으로 남기되, 두 문서를 잘라낼 이유가 없었다는 것이 결론입니다.

#### 발견 3 — 윤문 판정의 갈림선도 티어가 아니었습니다

§9.1은 "Tier A는 산문 라인으로 판정"으로 규정했고 §9.3이 "Tier C에서도 성립하니 갈림선은 보호 구간 비율일 것"이라고 의심했습니다. 표본 5건으로 확정됩니다 — **보호 구간이 39~55%로 전부 35%를 넘고, 윤문 문자율도 티어와 무관하게 1.06~2.32%에 몰려 있습니다.** 티어 A인 M2(1.48%)와 티어 C인 M4(1.06%) 사이에 규칙성이 없습니다.

→ **개정: §1 판정표의 기준을 티어에서 보호 구간 비율(35%)로 바꿉니다.** 실질적으로 모든 lesson이 산문 라인 판정 대상이 됩니다.

#### W1-M1의 티어 불일치 — A로 확정 (2026-08-05 해소)

`lesson.md`의 frontmatter는 **`tier: A`** 인데 §4 표 · §5 체크리스트 · §9.2 표 **세 곳이 B**로 적혀 있었습니다. 정적 사이트 빌드(§3.1)가 frontmatter만 스캔하므로 방치하면 목차와 계획이 어긋나는 상태였습니다. **A로 통일하고 계획 문서 세 곳을 고쳤습니다.**

근거 둘입니다.

- **실측이 A에 맞습니다.** 산문 25,161자는 A 밴드(24,000~28,000)에 들어가고 B 밴드(17,000~25,000)는 넘습니다.
- **내용이 A의 정의에 맞습니다.** W1-M1이 다루는 로봇 산업 지형·주요 플레이어 지도는 §3 갭 분석상 **경험 전무 영역**입니다. B의 정의("개념 자체는 익숙하나 로봇 맥락 재해석이 본체")와는 맞지 않습니다.

**§4의 모듈 배분이 A 7 + B 9에서 A 8 + B 8로 바뀌었습니다.** 합계 20은 그대로입니다. lesson·practice·labs 본문은 한 글자도 바꾸지 않았습니다 — 라벨만 정리한 것입니다.

#### 계산 스크립트

```python
import re
s = open('lesson.md').read()
total = len(s)
fm = re.match(r'^---\n.*?\n---\n', s, re.S)
struct = len(fm.group(0)) if fm else 0
for m in re.finditer(r'```.*?```', s, re.S): struct += len(m.group(0))
body = re.sub(r'```.*?```', '', s, flags=re.S)
for m in re.finditer(r'\$\$.*?\$\$', body, re.S): struct += len(m.group(0))
body2 = re.sub(r'\$\$.*?\$\$', '', body, flags=re.S)
struct += sum(len(l) + 1 for l in body2.split('\n') if l.strip().startswith('|'))
inline = sum(len(m.group(0)) for m in re.finditer(r'(?<!\$)\$[^$\n]+\$(?!\$)', body2))
print(f"총 {total} · 구조물 {struct}({struct/total:.1%}) · 산문 {total-struct} · 보호 {(struct+inline)/total:.1%}")
```

#### 집필 환경 변경 — practice 설계에 영향

W1 practice는 **WSL2 + RTX 3080 + Python 3.12**에서 검증했으나(각 `requirements.txt`에 기록), 이번 세션의 집필 환경은 **macOS + Homebrew Python 3.14.6이고 torch·numpy·lerobot이 전부 미설치**입니다. LeRobot은 Python 3.12를 요구하므로 3.14에서는 설치 자체가 막힙니다. 따라서 W2-M1 practice는 **표준 라이브러리만으로 도는 층**(지연 예산 계산 · 앙상블 가중 분석 · compounding error 토이 시뮬 — lesson의 수치를 학습자가 직접 재현하는 장치)과 **torch/LeRobot 층**(미검증 배지)으로 나눠 설계합니다. 앞 층은 집필 환경에서 실행 검증이 가능합니다.
