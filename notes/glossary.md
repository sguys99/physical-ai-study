# 용어집

> 매일 5개씩, 주차 종료 시 25개 누적. 4주 뒤 100개 내외가 목표입니다.
> 용어는 [마스터플랜 §3](../docs/physical-ai-4week-master-plan.md)의 용어 사전과 일치시킵니다.
> 형식: **약어/용어** — 한 줄 정의 · (있으면) 제어·ML·LLM 대응 비유 · 처음 만난 모듈

## 미리 채워둔 기본 약어 (마스터플랜 §3)

| 용어 | 정의 | 비유 / 메모 | 모듈 |
|---|---|---|---|
| **VLA** | Vision-Language-Action 모델. 시각·언어 입력에서 로봇 액션을 직접 출력 | VLM에 액션 디코더를 붙인 것 | W2-M3 |
| **WBC** | Whole-Body Control. 전신 관절을 협조 제어 | 다관절 시스템의 통합 제어기 | W3 |
| **WFM** | World Foundation Model. NVIDIA Cosmos처럼 범용 비디오 기반 월드모델 | 학습된 플랜트 모델 | W4-M2 |
| **WAM** | World-Action Model. 비디오 월드모델 백본에 액션을 latent frame으로 주입해 예측과 행동을 공동 생성 | 모델 + 정책 동시 학습 | W4-M2 |
| **IDM** | Inverse Dynamics Model. 연속 관측에서 그 사이의 액션을 역추정 | 역동역학 | W2-M5 |
| **OXE** | Open X-Embodiment. 여러 로봇 플랫폼의 시연 데이터를 통합한 데이터셋 | — | W2-M3 |
| **teleop** | 원격조작. 사람이 로봇을 직접 조종해 시연 데이터를 만드는 것 | — | W2-M1 |
| **retargeting** | 인간 모션 → 로봇 관절 매핑 | 좌표계·링크 길이 변환 | W3-M2 |
| **sim2sim** | 학습 시뮬레이터(Isaac/MJX) → 검증 시뮬레이터(표준 MuJoCo) 이식 검증 | 플랜트 모델 교차 검증 | W3-M5 |
| **FSQ** | Finite Scalar Quantization. 각 차원을 고정 레벨로 반올림하는 이산화 — codebook 없이 collapse 원천 차단 | **액션의 토크나이저** | W1-M5 |

## W1

### W1-M1 — Physical AI 개요와 산업 지형

| 용어 | 정의 | 비유 / 메모 | 모듈 |
|---|---|---|---|
| **Physical AI** | 인터넷 규모 데이터로 학습한 지능을 물리 법칙·실시간 제약이 있는 몸에 넣는 문제 | Embodied AI와 거의 동의어지만, 파운데이션 모델·시뮬 인프라를 포함한 **스택 전체**를 가리키는 뉘앙스(NVIDIA발 산업 용어) | W1-M1 |
| **스택 5계층 (L1~L5)** | L1 하드웨어·미들웨어 / L2 전신제어 WBC / L3 액션 인터페이스 / L4 상위 지능 / L5 인지·매핑 | 계층적 제어(supervisory·cascade control)의 재발견. **위로 갈수록 느리고 똑똑, 아래로 갈수록 빠르고 반사적** | W1-M1 |
| **대역폭 분리** | 인접 계층의 동작 주파수를 한 자릿수 이상 벌려 두 루프가 서로의 동특성에 간섭하지 않게 하는 원리 | 캐스케이드 제어의 inner/outer 5~10배 규칙. 다만 여기서는 설계 선택이 아니라 **연산 예산이 강제** | W1-M1 |
| **action chunking** | 상위 모델이 한 번의 추론으로 미래 여러 스텝의 액션을 한꺼번에 뱉는 것 | **MPC의 예측 지평 $N$** — 매 스텝 $N$개를 풀어 앞의 일부만 쓰고 버리는 receding horizon과 동형. 최적화 대신 신경망 회귀 | W1-M1 → W2-M1 |
| **지연 예산 / 명령 공백** | $H_{chunk} \ge f_2(T_{replan} + \tau_{infer} + \tau_{comm})$. 이를 못 채우면 하위 제어기가 쓸 명령이 없는 구간이 생김 | 청크 = 상위의 느림을 감추는 **버퍼**. 길수록 지연에 강하지만 반응성이 떨어짐 | W1-M1 → W4-M4 |
| **데이터 피라미드** | 웹 비디오 → 휴먼 비디오·모캡 → 텔레옵 시연 → 실기 RL. 위로 갈수록 양은 많고 액션 라벨은 없음 | 병목은 "데이터 부족"이 아니라 **라벨 없는 상단을 하단으로 끌어내리는 법** | W1-M1 → W2-M5 |
| **latent action** | 진짜 액션 대신 대리 액션 $z_t = E(o_t, o_{t+1})$을 학습하고, 소량 실기 데이터로 $z \to a$ 디코더만 맞추는 접근 | 라벨 없는 비디오를 쓰기 위한 우회로(LAPA·Genie 계열) | W1-M1 → W2-M5 |
| **크로스 임바디먼트** | 서로 다른 로봇 플랫폼의 데이터를 하나의 포맷으로 통합해 함께 학습하는 것 | OXE가 22종 로봇을 묶은 것이 대표. 단일 플랫폼 대규모(AgiBot World)와는 성격이 다름 | W1-M1 → W2-M3 |
| **universal token space** | 상위의 여러 입력원(VLA·VR 텔레옵·게임패드 플래너)을 하나의 공통 토큰 표현으로 받아 단일 WBC 정책에 물리는 설계 | SONIC의 핵심. **곧 L3 인터페이스 설계 문제** | W1-M1 → W3-M4 |
| **WBC 파운데이션 정책** | 대량 모캡을 스케일업해 학습한, 태스크 비특정 범용 전신 제어 정책 | SONIC = 42M 파라미터 / 700시간 모캡 / 21,000 GPU-hours | W1-M1 → W3-M4 |

### W1-M2 — 시뮬레이터 부트캠프

| 용어 | 정의 | 비유 / 메모 | 모듈 |
|---|---|---|---|
| **MJCF** | MuJoCo의 로봇·장면 기술 XML. `<option>` `<default>` `<worldbody>` `<actuator>` `<sensor>` `<keyframe>`으로 구성 | URDF의 MuJoCo판. 다른 점은 **접촉·solver 설정까지 같은 파일에 든다**는 것 — 모델과 적분기 설정이 분리돼 있지 않음 | W1-M2 |
| **`mjModel` / `mjData`** | 컴파일 결과인 상수(관성·링크·게인·solver 옵션) vs 매 스텝 변하는 상태와 중간량 | 상태공간 모델의 $(A,B,C,D)$와 $x(t)$ 분리와 같음. **MJX가 모델 1개 + 데이터 N개로 GPU 병렬을 하는 전제** | W1-M2 → W3-M1 |
| **`nq` ≠ `nv`** | 위치 좌표 수와 속도 자유도 수가 다른 현상. G1은 36 vs 35 | 자유 관절 회전을 쿼터니언 4수로 표현하지만 실제 회전 자유도는 3(‖q‖=1 제약). **위치는 과잉좌표 다양체, 속도는 그 접선공간** | W1-M2 |
| **MJX** | MuJoCo를 JAX로 재구현해 `vmap`으로 수천 환경을 GPU에서 병렬 적분하는 백엔드 | 같은 수식, 다른 튜닝. G1 기준 `timestep` 0.002→0.004 · `iterations` 100→5로 **정확도를 처리량과 맞바꿈** | W1-M2 → W3-M1 |
| **position 액추에이터** | $f = k_p(\texttt{ctrl} - q) - k_v \dot q$ 를 내는 MuJoCo 액추에이터. **`ctrl`은 토크가 아니라 목표 관절각[rad]** | 실기 온보드 PD 서보를 시뮬레이터가 이미 모사하고 있는 것. 정책이 내보내는 것은 토크가 아니라 setpoint | W1-M2 → W3-M5 |
| **`dampratio`** | PD 게인을 감쇠비 $\zeta$로 지정하는 MJCF 속성. $k_v = 2\zeta\sqrt{k_p M_{\text{eff}}}$ | G1은 `dampratio="1"`(임계감쇠)이라 **`kv`가 관절마다 다름**(43.01 / 15.85 / 9.43). 역산하면 관절 유효관성이 나옴 | W1-M2 |
| **`armature`** | 관절에 더해지는 반사 관성(rotor inertia). G1은 전 관절 0.01 | 감속기 뒤 모터 로터가 관절에서 보이는 등가 관성. 실기에서는 관절마다 다르므로 **sim2real 갭의 씨앗** | W1-M2 → W3-M5 |
| **`solref` / `solimp`** | 접촉·제약을 무한 강성 대신 스프링-댐퍼로 완화하는 soft-constraint 파라미터 | 상보성 조건(LCP)의 매끄러운 근사. 뻣뻣할수록 정확하지만 `timestep`을 줄여야 함 | W1-M2 |
| **`MUJOCO_GL`** | 렌더링 백엔드 선택 환경변수. `egl`(GPU 오프스크린) / `osmesa`(소프트웨어) / `glfw`(디스플레이 필요) | 클라우드는 `egl`. **`import mujoco` 이전에 설정**해야 적용됨 — 순서를 틀리는 것이 입문 최다 실수 | W1-M2 |
| **`n_substeps`** | 정책 한 스텝 동안 물리를 몇 번 적분하는가. `ctrl_dt / sim_dt` | `G1JoystickFlatTerrain`은 0.02 / 0.002 = **10**. 정책 50 Hz · 물리 500 Hz로 W1-M1 주파수 예산의 L2 대역과 정확히 일치 | W1-M2 → W4-M4 |
