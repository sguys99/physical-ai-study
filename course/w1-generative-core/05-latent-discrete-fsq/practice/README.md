
## 3. 데이터 — 어떻게 만들고 어떻게 정규화하나

별도 다운로드 없이 재현 가능해야 하므로 궤적을 **MuJoCo G1 모델에서 직접 생성**합니다.
회사가 FSQ로 토큰화하는 대상은 이미지가 아니라 **액션**이므로(lesson §7), 데이터도 액션이어야 합니다.

### 3.1 정규화 규약 — 관절별 `jnt_range`를 [-1, 1]로

```
x_j = 2·(q_j − lo_j)/(hi_j − lo_j) − 1        # eq.(6)
q_j = lo_j + (x_j + 1)/2·(hi_j − lo_j)        # 역변환
```

`lo`/`hi`는 G1 `scene.xml`의 `actuator_ctrlrange`입니다. W1-M2 lesson §5.5에서 확인했듯
`<position ... inheritrange="1"/>`이라 **`ctrlrange = jnt_range`** 이고, 따라서 `x ∈ [-1,1]`이면
언제나 관절 한계 안입니다.

**관절마다 가동범위가 11배까지 다릅니다** — 최소 `left_ankle_roll` 0.524 rad(30°),
최대 `left_shoulder_pitch` 5.760 rad(330°). 그래서 **같은 정규화 오차가 라디안으로는 11배 차이**가
납니다. `03`이 관절별로 라디안·도로 환산해 보여주는 이유입니다.

### 3.2 궤적 3종 + 관절 시너지

| 종류 | 생성 방식 |
|---|---|
| `sine` | 3-성분 sin 합, 0.15~1.2 Hz (W1-M2 `03_g1_sin_wave.py`의 확장) |
| `waypoint` | 랜덤 목표 3~6개를 smoothstep 보간 |
| `reach` | `stand`에서 랜덤 포즈로 갔다 오기 (minimum-jerk) |

셋을 무작위로 섞습니다. 샘플링 레이트는 **50 Hz**(W1-M2 ground-truth의 `G1JoystickFlatTerrain`
정책 주기 `ctrl_dt=0.02`와 같은 시간 격자).

**관절 시너지** — 궤적을 `n_syn`차원 계수 공간에서 만든 뒤 고정 기저 `B [n_syn, 29]`로 관절 공간에 올립니다.

```
x(t) = clip(x_stand + c(t)·B, −1, 1),   c(t) ∈ R^n_syn     # eq.(7)
```

실제 휴머노이드 모션은 관절이 강하게 상관돼 저차원 구조를 갖습니다. 29개 관절을 서로 **독립적으로**
흔든 궤적에는 그런 구조가 없어서 **어떤 토크나이저로도 압축되지 않습니다** — 토큰 하나(10 bits)로
담을 상관구조가 애초에 없기 때문입니다.

`--synergies 0`으로 `B = I₂₉`를 주면 그 대조군을 직접 볼 수 있습니다(§6의 심화 과제 참조).
`B`는 **학습셋과 검증셋이 같은 것**을 씁니다(같은 다양체 위의 데이터여야 하므로).

> 회사 토크나이저의 학습 데이터가 무엇인지는 lesson §7.4대로 **미확인**입니다.

## 5. 결과를 어떻게 읽는가

### 5.1 `01` — FSQ가 정말 40줄인가

- **`nn.Parameter`가 0개**라는 출력이 이 스크립트의 결론입니다. 코드북이 없으니 **죽을 코드가 없습니다.**
- assert 5종(왕복 · 인덱스 범위 · 유일성 · STE · 채널별 레벨 수)이 전부 통과하면 구현이 맞는 것입니다.
  특히 **짝수 L(`[4,4]`·`[8,8]`)에서도 격자가 정확히 L개**인지 확인합니다 —
  원논문이 "짝수 L에는 비대칭 f가 필요하다"고 명시한 부분입니다.
- Table 1 검산에서 **`prod/target` 열이 1.000이 아닙니다**(0.938 / 0.977 / 1.068 / 0.938 / 0.977).
  코드북 크기가 2의 거듭제곱이어야 할 이유가 없습니다 — 논문 표현도 "approximately match"입니다.
- `01_fsq_bound_round.png` **오른쪽 패널이 핵심**입니다. `round`의 진짜 미분은 거의 모든 곳에서 0(빨간 바닥선)이고,
  STE는 그 자리에 `f'(z)`를 꽂습니다(파란 종 모양). **STE가 없으면 인코더로 학습 신호가 흐르지 않습니다.**
- `01_fsq_grid.png` **(a)의 바깥 셀이 넓은 것**을 보세요. `tanh` 포화 구간의 모든 `z`가 같은 토큰으로 갑니다 —
  유계화의 대가입니다.

### 5.2 `02` — 사용률 그래프에서 무엇을 봐야 하는가 ★

**집필 환경 실측** (`--sweep`, 기본 하이퍼파라미터, seed 0):

| 구성 | \|C\| | d | 쓰인 코드 | **사용률** | ppl | val MSE | vs 기준선 | RMSE | 양자화기 param |
|---|---|---|---|---|---|---|---|---|---|
| FSQ `[8,6,5]` | 240 | 3 | 240 | **100.0%** | 113 | 0.00781 | 36% | 8.39° | **0** |
| VQ 2^8 | 256 | 64 | 214 | 83.6% | 156 | **0.00589** | 27% | 7.32° | 16,384 |
| FSQ `[8,5,5,5]` | 1,000 | 4 | 968 | **96.8%** | 323 | 0.00583 | 27% | 7.23° | **0** |
| VQ 2^10 | 1,024 | 64 | 216 | 21.1% | 157 | 0.00586 | 27% | 7.28° | 65,536 |
| FSQ `[7,5,5,5,5]` | 4,375 | 5 | 3,145 | **71.9%** | 732 | **0.00424** | 19% | 6.17° | **0** |
| VQ 2^12 | 4,096 | 64 | 185 | **4.5%** | 133 | 0.00611 | 28% | 7.44° | 262,144 |

읽는 순서:

1. **`02_usage.png` (a) — 사용률이 갈리는 지점.** 2^8에서는 두 방법이 비슷하고(100% vs 84%),
   코드북을 키울수록 VQ가 무너집니다(21% → **4.5%**). FSQ도 71.9%로 떨어지지만 **비교가 안 됩니다.**
   원문 Fig 3의 축소 재현입니다.
2. **`02_usage.png` (b) — 복원 곡선이 2^10에서 교차합니다.** 이것이 lesson §5.5가 강조한 **공정성**입니다.
   작은 코드북(2^8)에서는 **VQ가 더 잘 복원하고**(0.00589 vs 0.00781), 2^10에서 사실상 동률이며
   (0.00583 vs 0.00586), 2^12를 넘어서면 FSQ가 앞서고 **VQ는 오히려 나빠집니다**(0.00424 vs 0.00611).
   "FSQ가 항상 낫다"는 틀린 요약입니다.
3. **`02_code_hist.png` 오른쪽(VQ) — 절벽.** 곡선이 21%·4.5% 지점에서 수직으로 바닥에 떨어집니다.
   그 오른쪽 전부가 **한 번도 안 쓰인 코드 = 죽은 코드**입니다. 왼쪽(FSQ)은 매끄러운 꼬리를 그립니다.
   **이 그림 한 장이 lesson §4.1 codebook collapse의 실물 증거입니다.**
4. **파라미터.** FSQ는 양자화기 파라미터 **0개**, VQ는 2^12에서 262,144개. lesson 퀴즈 8번의
   "2M vs 0" 을 축소한 숫자입니다.
5. **사용률만 보고 결론내지 마세요.** `val MSE` 열을 반드시 같이 보세요 —
   lesson 「흔한 오해」 2번("사용률 100%면 표현력이 최대다")가 바로 이 함정입니다.

**사용률의 상한**은 스크립트가 매번 찍어줍니다.

```
usage ≤ min(1, N_val_tokens / |C|)
```

청크 하나가 토큰 하나이므로 **검증셋이 코드북보다 충분히 커야** 사용률이 의미를 갖습니다.
기본 설정은 검증 토큰 28,800개(= 코드북 4,096의 7배)라 상한이 100%입니다. 이미지 토크나이저는
이미지 한 장이 토큰 수백 개를 만들어 이 문제가 없지만, **액션 토크나이저는 평가 설계에서
이것부터 걸립니다.** 코드북을 2^14 이상으로 키울 때는 `--n-val-traj`도 같이 키우세요.

`--smoke`는 상한 자체는 100%지만 **6 epoch만 돌아 학습이 덜 된 상태**입니다
(실측: 스모크에서 FSQ 사용률이 40%대까지밖에 안 올라갑니다). **스모크의 사용률 숫자를
결론에 쓰면 안 됩니다** — 스크립트도 실행 첫 줄에 그렇게 경고합니다.

#### VQ에 트릭을 켜면? — 실측

기본은 **트릭을 전부 끈 바닐라 VQ**입니다(코드북 `uniform(-1/K, 1/K)` 초기화, EMA 없음).
그것이 FSQ 논문의 논지이기 때문입니다. 켜본 결과(|C|=1024, 40 epoch, 같은 시드):

| 명령 | VQ 사용률 | val MSE |
|---|---|---|
| (기본) 바닐라 | **21.1%** | 0.00586 |
| `--vq-init data` | 19.5% | — |
| `--vq-ema` | 18.8% | 0.00591 |
| `--vq-init data --vq-ema` | 18.3% | 0.00592 |

> **이 장난감 설정에서는 트릭이 도움이 되지 않았습니다.** "코드북 재초기화·EMA를 넣으면 해결된다"가
> 자동으로 성립하지 않는다는 관측입니다. 이 값들은 **이 설정의 실측**이지 일반 법칙이 아닙니다 —
> 논문 규모의 실험에서는 트릭이 효과를 냅니다(그래서 lesson §4.1의 표에 6가지가 쌓인 것입니다).
> 요점은 "FSQ는 그 표 자체가 필요 없다"입니다.

### 5.3 `03` — 이 정밀도로 로봇을 제어할 수 있는가

- **토큰 열**이 stdout과 `03_tokens.txt`에 그대로 찍힙니다. 기본 시드의 실측 출력(480프레임 → 30개):

  ```
  499 499 540 540 548 548 548 588 588 597 597 797 797 797 797
  797 797 797 797 797 989 949 949 949 949 901 901 893 853 853
  ```
  **이게 LLM vocabulary에 그대로 들어갈 수 있는 형태**라는 것이 요점입니다(lesson §1.1 이유 ①·②).
- **인접 청크가 같은 토큰을 반복하는 구간**이 보입니다. 동작이 느릴 때 나타나며,
  상위가 "토큰을 유지"하는 것과 하위가 "마지막 토큰을 홀드"하는 것이 같은 결과를 낸다는 뜻입니다
  (lesson §7.2 sequenceDiagram).
- `--demo-seed`를 바꿔 대칭 동작(갔다 돌아오기)을 뽑으면 **토큰 열이 회문(palindrome)** 이 됩니다.
  토큰 열이 동작의 구조를 그대로 반영한다는 증거입니다.
- **`03_overlay.png`가 이 스크립트의 핵심 그림입니다.** 복원 궤적이 **계단(zero-order hold)** 으로
  원본을 따라갑니다 — lesson §3의 **DAC 분해능** 비유가 그림으로 나온 것입니다. 계단 하나가 청크 하나,
  즉 토큰 하나입니다.
- **복원 오차 실측**(`--sweep` 체크포인트, `--demo-seed 789`): 전체 평균 RMSE **5.88°**,
  최악 관절 `right_shoulder_yaw` **12.00°**(최대 순간 오차 24.9°), 최선 관절 `right_ankle_roll` **0.98°**.
  위치 제어 로봇의 반복 정밀도가 보통 0.1° 수준인 것과 비교하면 **이 토큰 하나로 관절 명령을 직접
  만들 수는 없습니다.** 그게 lesson 「흔한 오해」 3번의 요점입니다 — 토큰은 **의도의 해상도**이지
  관절 명령의 해상도가 아니고, 관절 명령은 하위 WBC가 50~500 Hz로 만듭니다.
- **`03_joint_error.png` (b)** 에서 오차가 가동범위에 비례하는 것을 보세요. 정규화 공간에서 일하기
  때문이며(eq.(6)), **관절별 가중치를 손실에 넣을지**가 실무 설계 결정이 되는 지점입니다.
- **압축률**은 lesson §6·퀴즈 9번과 **정확히 같은 숫자**가 나옵니다:
  원본 `16 × 29 × 32 = 14,848 bits`, 토큰 `log2(1000) = 9.97 bits`, 압축률 **1,489.9배**
  (10비트로 저장하면 1,484.8배). 스크립트가 이 값을 `assert`로 검증합니다.
- **mp4는 물리를 끄고 관절각만 재생합니다**(`mj_forward`). `--physics`를 주면 PD 서보로 실제 물리를
  돌리는데 **로봇이 넘어집니다** — W1-M2 `03_g1_sin_wave.py --joints legs`와 같은 이유이고,
  토크나이저 탓이 아니라 **균형을 지킬 WBC가 없기 때문**입니다. 그 WBC를 학습으로 얻는 것이 W3-M1입니다.

```bash
# ① 코드북을 더 키우면? Table 1의 2^14 행. 검증셋도 같이 키워야 사용률이 의미를 갖는다

python 02_fsq_vs_vq_g1.py --synergies 12      # 반대로 더 복잡한 다양체

# ③ 청크당 토큰 수 — lesson §7.4의 "프레임당 1토큰인가 청크당 N토큰인가"를 직접 만져본다

python 03_g1_action_tokenizer.py --retrain --tokens-per-chunk 4

# ④ VQ에 트릭 켜기 — §5.2의 실측표를 직접 재현
python 02_fsq_vs_vq_g1.py --vq-init data --vq-ema

# ⑤ 청크 길이 — 길수록 압축률↑ 시간 해상도↓
python 02_fsq_vs_vq_g1.py --chunk 32 --stride 16

# ⑥ 물리를 켜서 넘어지는 것 보기 (W1-M2 §03의 재확인)
MUJOCO_GL=egl python 03_g1_action_tokenizer.py --physics --demo-len 240

# ⑦ 격자 시각화를 다른 레벨로
python 01_fsq_minimal.py --levels 7,5,5,5,5
```

> 체크포인트 파일명에 구성이 박히므로(`_smoke` / `_n4` / `_syn0`) 변형 실행이 본 학습 결과를
> 덮어쓰지 않습니다. `03`은 기본 이름(`fsq_g1_L8-5-5-5_T16.pt`)을 찾습니다.

**②·③의 실측 결과** (15 epoch, |C|=1000 vs 1024 — 기본 설정은 40 epoch이므로 값이 조금 다릅니다):

| 변형 | FSQ 사용률 | FSQ val MSE (기준선 대비) | FSQ RMSE | VQ 사용률 | VQ RMSE |
|---|---|---|---|---|---|
| ② `--synergies 0` | 92.8% | 0.02860 (**86%**) | 17.22° | 14.4% | 17.21° |
| (기준: 시너지 6, 40 ep) | 96.8% | 0.00583 (27%) | 7.23° | 21.1% | 7.28° |
| ③ `--tokens-per-chunk 4` | **100.0%** | 0.00103 (**5%**) | **3.04°** | 10.3% | 5.25° |

- **②가 말하는 것**: 관절이 서로 독립이면 토큰이 베이스라인 대비 14%밖에 못 법니다(86% 잔존).
  **압축은 데이터에 구조가 있을 때만 가능합니다.** "무엇을 버려도 되는가"가 학습 데이터 분포에
  달려 있다는 lesson §6의 문장이 숫자로 나오는 지점입니다.
- **③이 말하는 것**: 청크당 토큰을 4개로 늘리면 복원 오차가 7.2° → 3.0°로 떨어지고 FSQ 사용률은
  100%가 됩니다. **압축률(1,489 → 372배)과 정밀도의 트레이드오프**이고, 이 곡선의 어디에 앉을지가
  곧 토큰 레이트 설계입니다 — lesson §7.4의 팀 질문 2번이 묻는 것입니다.
  여기서는 VQ와의 격차가 사용률뿐 아니라 **복원에서도** 벌어집니다(3.04° vs 5.25°).

`torch`가 CPU 빌드입니다. §1.1의 `--index-url .../cu130`로 다시 설치하세요.
`01`은 어차피 GPU를 안 쓰므로 이 메시지가 나와도 정상입니다.

### ③ 종료할 때 뜨는 EGL traceback

```
Exception ignored in: <function Renderer.__del__ at 0x...>
OpenGL.raw.EGL._errors.EGLError: <exception str() failed>
```

**무해합니다.** `Exception ignored in:`으로 시작하면 파이썬이 이미 그 예외를 무시했다는 뜻입니다.
`[저장] ...` 줄이 찍혔는지만 확인하면 됩니다(W1-M2 README §3의 함정 ①과 동일).

### ④ 사용률이 이상하게 낮다 (`--smoke`에서)

스모크는 6 epoch만 돌아 **학습이 덜 된 상태**입니다(FSQ가 40%대에 머뭅니다). 결론은 본 실행에서 내세요.
코드북을 크게 키운 경우라면 `사용률 상한=xx%` 출력도 확인하세요 — 검증 토큰 수가 코드북보다
작으면 100%가 애초에 불가능합니다.

### ⑤ `03`이 "체크포인트가 없어 짧게 학습합니다"라고 한다

`02`를 아직 안 돌렸거나, `--levels`/`--chunk`가 `02`와 다릅니다.
체크포인트 이름은 `fsq_g1_L{레벨}_T{청크}.pt` 규칙입니다.
